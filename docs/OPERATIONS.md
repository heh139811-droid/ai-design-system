# 공통 레포 운영

## 레포 경계
이 폴더만 독립 GitHub 레포에 올린다. 상위 backend_infra_testing 전체나 환경 설정·비밀값을 올리지 않는다.
제안 이름은 wonjeongdae-design-system이며 회사 자료이므로 비공개를 기본으로 한다.

## 업데이트
1. 브랜드 담당자가 원본 색/규칙 변경을 확인한다.
2. tokens/brand.json 또는 DESIGN.md를 PR로 수정한다.
3. npm run build, npm test, npm run check와 examples/index.html 육안 검증을 수행한다.
4. 새 버전 태그를 발행한다. 연결 프로젝트는 커밋/태그를 고정하고 PR로 갱신한다.
5. 복사 방식 소비자는 새 폴더에 다시 도입하고 diff 후 경로를 갱신한다. 중앙 수정이 모든 사이트에 즉시 강제 반영되지는 않는다.

## 초기 완성 범위
- 실제 구현: 6색 토큰, 2개 테마, CSS 생성, 기본 UI 클래스, 파일 도입 CLI, AI 지침, 대비 검사, 예제.
- 최초 AI 작업 필요: 기존 사이트 변수 매핑, 하드코딩 색 정리, 포털과 CSS 우선순위 처리, 화면 검증.
- 추가 개발 필요: React 컴포넌트 패키지, Astryx 전용 어댑터, Figma Variables/Code Connect, 프린트/네이티브 어댑터.
- 원본 확보 필요: 로고 SVG, 폰트/라이선스, 사진, 확정 레이아웃/모션 규격.

## 성공 기준
새 프로젝트에서 공통 레포 가이드를 읽도록 한 번 지시하면 AI가 설치·매핑·검증을 수행할 수 있어야 한다.
이미 연결된 프로젝트에서는 공통 토큰 버전 갱신으로 색이 반영돼야 한다.
임의의 기존 사이트를 코드 수정 없이 바꿀 수 있다는 의미로 설명하지 않는다.
